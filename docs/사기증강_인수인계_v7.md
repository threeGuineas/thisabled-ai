# 인수인계 — SAFE 이진 v7 금전 사기 커버리지 보강

> 다음 세션이 사실 상태를 재확인한 뒤 이어서 실행하기 위한 문서다.
> 브랜치: `feature/safe-scam-augmentation`, 기준 HEAD `0a67116` + 로컬 미커밋 변경.
> 정본 계획: [사기증강_재학습_계획_v7.md](사기증강_재학습_계획_v7.md)

## 목표와 결정

- SAFE 이진 모델(정상/주의)의 금전 사기 공백을 데이터와 재학습으로 보강한다.
- Gemini 합성 + 별도 LLM 라벨·문장논리 검수 + 사람 승인을 코어 흐름으로 사용한다.
- 자동 검수만 통과한 데이터는 학습하지 않는다. 후보 파일과 검수 보고서의 SHA-256을
  사람이 승인한 뒤에만 canonical 학습 파일로 승격한다.
- PsyScam·보이스피싱 벤치마크는 라이선스와 접근성을 확인한 뒤 선택적으로 추가한다.

## 구현된 안전 경계

- `src/data/llm_client.py`
  - API 키를 URL이 아닌 헤더로 전달한다.
  - 408·429·5xx와 전송 오류를 제한된 지수 백오프로 재시도한다.
  - 긴 `Retry-After`가 로컬 최대 대기보다 크면 조기 재호출하지 않고 종료한다.
  - 응답 크기 제한, multi-part 텍스트 결합, thought part 제외, 구조화 오류를 적용했다.
- `src/data/scam_synthesis.py`
  - 사기 6유형과 정상 금전 경계 3유형을 정확한 label/subtype 계약으로 생성한다.
  - 전화·계좌·주민번호·OTP·상품권 PIN·URL·이메일과 흔한 유니코드 우회를 제거한다.
  - 내부 중복과 forbidden exact/near duplicate를 제거한다.
  - 라벨·품질 검수는 20건 배치 완료 단위로 재개할 수 있다.
- `scripts/build_scam_dataset.py`
  - forbidden 입력은 기본 필수이며, 빈 파일·경로 충돌·조상/자손 충돌을 API 호출 전에
    거부한다.
  - 합성 캐시는 schema v2, 검수 체크포인트는 schema v3이다.
  - label/quality 체크포인트의 값·수량·배치 경계·입력 SHA를 fail-closed로 검증한다.
  - subtype마다 요청 수량을 정확히 채우고, 각 검수 단계 뒤 기본 80% 보존을 요구한다.
  - 기본 출력은 `outputs/10_thisabled-ai/데이터/YYYYMMDD_thisabled_사기학습후보.jsonl`이다.
    승인 전 CLI가 `data/synthetic/scam/train.jsonl`에 직접 쓰는 것은 거부한다.
  - 최종 후보와 검수 보고서를 함께 준비한 뒤 교체한다. 보고서 교체 실패 시 기존 후보를
    복구하며, 복구 자체가 실패하면 유일한 백업을 삭제하지 않고 경로를 오류로 남긴다.
- `src/training/trainer.py`, `configs/module1_binary_hardcases_v7.yaml`
  - canonical 사기 데이터는 승인 manifest가 없거나 데이터·보고서 SHA가 다르면 학습
    로더가 거부한다. config에서 manifest 매핑을 빼는 방식으로도 우회할 수 없다.
- `scripts/adapt_external_datasets.py`, `scripts/build_final_dataset.py`
  - 외부 direct source의 exact key는 공백·구두점·대소문자를 무시하면서 한글 자모를
    보존한다.
  - adapter는 glob을 쓰지 않고 소비된 blind v1~v9만 명시적으로 읽으며, 실 holdout과
    grooming 개발셋도 함께 제거 기준으로 쓴다.
  - base train 빌드는 `--forbidden`으로 명시한 소비 평가셋의 exact/near 중복을 최종
    train에서 제거한다. future v10을 자동 발견해 데이터 선택에 쓰지 않는다.
- `notebooks/13_scam_augmentation_v7_colab.ipynb`
  - 현재 VS Code/Colab 작업 디렉터리를 우선 탐색하고 필요할 때만 clone한다.
  - 이미 있는 eval JSONL 3개와 PAN12는 고정 SHA를 먼저 확인한다. 새 런타임에서는
    VS Code 경로의 `data_bundle_eval.zip`에서 정확히 필요한 eval JSONL 3개만 허용하고,
    PAN12는 별도 정본 경로로 받는다. `data/eval` symlink·암호화·총 해제 크기를 검증한
    뒤 원자 추출한다.
  - 본 생성은 outputs 후보로만 저장한다. 별도 3b 셀의 명시적 사람 승인과 두 SHA가
    일치해야 canonical train과 approval manifest를 만든다.
  - 본 생성의 `RUN_DATE`는 최초 실행일로 고정하며, 같은 날 새 품질 라운드만
    `RUN_VERSION=2, 3, ...`으로 올린다.
  - 학습 전·반복별·업로드 전에 승인 산출물을 다시 검증한다.
  - v9 정본 SHA를 고정해 개발 회귀셋으로 취급한다. 후보를 고정하기 전에 실제
    학습 입력 전체와 실 holdout·blind v1~v9·grooming 개발셋의 exact/near duplicate를
    거부한다. 최종 1회 평가는 독립 작성·봉인된 v10만 허용하며, v10도 이 모든 학습·개발
    텍스트와 중복이면 폐기한다.
  - v10은 정확히 40행·20/20이고 필수 사기 5개 슬라이스가 각 3행 이상,
    `benign_money`가 8행 이상이어야 한다.
  - fresh v10 평가 전, 고정 Drive registry에 v10 SHA 소비 lock과 시작 ledger를
    기록하고 승인 데이터, 보고서, manifest, checkpoint, blind 정본과 결과를 보존한다.
    날짜·런타임·ledger 경로를 바꾼 재실행도 거부한다.
  - 업로드 셀은 재접속 뒤에도 영속 ledger만으로 모든 SHA·평가 결합·게이트를 다시
    계산할 수 있다. result의 40개 원시 예측을 blind 행과 strict 결합하고 audience별
    threshold 판정, confusion matrix, overall/by-slice 지표를 처음부터 재산출한다.
  - HF 업로드는 `UPLOAD_TO_HF=False`가 기본값이다.

## 다음 실행 순서

### 1. 새 파일럿 후보 생성

기존 캐시·보고서를 재사용하지 말고 다음처럼 명시적 후보 경로를 사용한다.

```bash
python scripts/build_scam_dataset.py \
  --per-subtype 5 \
  --synth-model gemini-3.5-flash \
  --verify-model gemini-3.5-flash \
  --request-interval 15 \
  --min-retention-ratio 0.8 \
  --out outputs/10_thisabled-ai/데이터/20260728_thisabled_사기파일럿후보_v4.jsonl \
  --synthesis-cache outputs/10_thisabled-ai/데이터/20260728_thisabled_사기파일럿체크포인트_v4.json \
  --verification-report outputs/10_thisabled-ai/데이터/20260728_thisabled_사기파일럿검수보고서_v4.json \
  --forbidden data/eval/aihub_real_holdout.jsonl \
  --forbidden data/eval/beep_real_holdout.jsonl \
  --forbidden data/synthetic/emergency/3a/val.jsonl \
  --forbidden data/synthetic/emergency/3a/test.jsonl \
  $(for i in $(seq 1 9); do echo --forbidden tests/fixtures/safe_blind_v$i.jsonl; done)
```

- `GEMINI_API_KEY`는 환경변수로 전달한다.
- 429가 나면 같은 명령으로 배치 체크포인트에서 재개한다.
- 45행 전수를 사람이 `keep/revise/drop`으로 검수한다.
- `drop=0`이고 revise 원인이 프롬프트·검수 기준에 반영됐을 때만 다음 단계로 간다.

### 2. 본 생성과 사람 승인

- Colab 노트북 셀 3에서 유형별 40건 후보를 생성한다.
- 새 clone이라면 고정 SHA의 eval 3파일 전용 `data_bundle_eval.zip`과 PAN12 정본 경로를
  셀 2에 준비한다. 과거 전체 `data_bundle.zip`은 사용하지 않는다.
- 셀 3의 `RUN_DATE`에 최초 실행일 8자리를 입력하고 429 재개 중에는 바꾸지 않는다.
  같은 날 사람 검수에서 탈락해 새로 생성할 때만 `RUN_VERSION`을 올린다.
- 검수 보고서와 subtype별 표본을 확인한다.
- 생성 셀을 다시 실행하지 않고, 출력된 후보·보고서 SHA를 셀 3b에 붙여넣는다.
- `HUMAN_QUALITY_APPROVED=True`로 바꾼 승인 셀만 실행해 canonical train과
  `data/synthetic/scam/approval.json`을 만든다.

### 3. 재학습과 개발 게이트

- 노트북에서 repeat 1→3을 순차 실행하고 첫 개발 게이트 통과 후보를 고정한다.
- Cell 5를 실행할 때 `safe_blind_v10.jsonl`은 존재하면 안 된다. 외부 adapter와 base
  builder는 고정된 소비 평가셋만 사용하고, 전체 학습 입력↔개발셋 guard가 0건이어야 한다.
- 개발 회귀셋은 실 holdout + 이미 소비된 blind v1~v9이다.
- 추가 게이트: `scam_recall≥0.80`, `benign_money_specificity≥0.875`.

### 4. 독립 fresh v10 작성과 단 한 번의 평가

- Cell 7에서 학습 후보를 고정한 뒤에만, 학습 데이터 작성과 분리된 작성자가 v10을
  `tests/fixtures/`에 배치한다.
- 정본 SHA-256을 별도로 전달하고 노트북 `FRESH_BLIND_EXPECTED_SHA`에 입력한다.
- 평가 전 Google Drive의 고정 경로
  `/content/drive/MyDrive/thisabled-ai/fresh_blind_registry`를 준비하고, 그 안의
  `.registry_id`에 `thisabled-ai-fresh-blind-registry-v1`을 정확히 기록한다.
  VS Code가 연결된 Colab 런타임에서 이 Drive 경로가 미리 마운트되어 있어야 하며,
  경로·marker가 없거나 다르면 평가를 시작하지 않는다.
- v10 SHA별 소비 lock은 고정 registry에 배타적으로 생성한다. 업로드 셀도 같은 marker,
  ledger, lock 및 보존 산출물의 결합을 다시 검증하므로 다른 폴더로 복사한 ledger는
  사용할 수 없다.
- v10은 40행·label 20/20, 필수 사기 슬라이스별 최소 3행,
  `benign_money` 최소 8행을 만족해야 한다.
- 게이트: 전체 risk recall ≥ 0.80, specificity ≥ 0.90, 위험 슬라이스 최소 recall ≥ 0.75,
  benign_money specificity ≥ 0.875.
- 소비 lock 또는 시작 ledger가 생기면 성공·실패와 관계없이 v10은 소비된 것으로 본다.

### 5. 배포

- fresh v10 게이트를 통과한 경우에만 사용자가 고정 registry 안의 영속 소비 ledger
  경로를 입력하고 `UPLOAD_TO_HF=True`를 명시한다. 업로드 시작 상태도 ledger와
  소비 lock 양쪽에 먼저 기록되므로, 중단 후 자동 재시도하지 않는다.
- 업로드 후 새 revision을 서빙 설정에 반영하고 `/health.revision`을 확인한다.

## 절대 지킬 규약

- 실제 개인정보를 합성 데이터에 넣지 않는다.
- 자동 검수 통과를 사람 승인으로 간주하지 않는다.
- v9를 fresh blind로 보고하지 않는다.
- v10을 학습·튜닝·재평가에 사용하지 않는다.
- 게이트 기준 완화, 의존성 추가, 외부 데이터 라이선스 결정, HF 업로드는 사용자 승인 없이
  진행하지 않는다.
- 저장소에는 다른 작업의 미커밋 변경이 함께 있으므로 관련 없는 파일을 되돌리지 않는다.
