# SAFE 이진 v7 — 금전 사기 커버리지 보강 (합성 + LLM 검수 + 재학습)

상태: 파이프라인 코어 구현·오프라인 검증 완료. 데이터 방향 (b) 결정 — PsyScam(공개)/
Gemini 합성 위주로 착수, 보이스피싱 벤치마크는 접근 확인 후 씨앗으로 얹는다.

## 배경

`docs/safe_데이터셋_확장_후보.md` §2-A 진단: **금전 사기 = 최대 공백.** 실 학습 데이터가
없어 규칙 레이어(RULE_ASSIST)로만 임시 보완했고 그마저 "ineffective"로 꺼둠. 근본 해결은
사기 데이터 확보 + 재학습. v6 외부데이터 재학습 패턴을 그대로 타되 사기 소스 + LLM 라벨
검수를 얹는다.

## 결정 (2026-07-22)

- A2(외부 데이터 + 재학습) + B2(LLM 오프라인 라벨 검수).
- 데이터 (b): 실데이터 접근 불확실 → **Gemini 합성 + LLM 검수를 코어로 먼저 가동**,
  PsyScam/보이스피싱 벤치마크는 확보되는 대로 씨앗·검증 기준으로 추가.
- LLM: 기존 Gemini 인프라 재사용(`gemini-flash-latest`), API 키 준비됨.

## 구현 (완료 — 오프라인 검증)

- `src/data/llm_client.py` — 주입 가능한 Gemini 클라이언트(429 백오프, 안전필터 해제).
- `src/data/scam_synthesis.py` — 사기 6유형(주의=1)·경계 반례 3유형(정상=0) 프롬프트,
  `synthesize_scam(generate)` + `verify_labels(generate)`. LLM 호출은 주입식.
- `scripts/build_scam_dataset.py` — 합성 → LLM 검수 → `data/synthetic/scam/train.jsonl`.
- `configs/module1_binary_hardcases_v7.yaml` — v6 ⊇ + 사기 소스.
- `tests/test_scam_synthesis.py` — fake LLM으로 합성·검수·파싱 파이프라인 검증(4개 통과).

## 실행 순서

### S1. 데이터 생성 (사용자, Gemini 키 필요)
```bash
export GEMINI_API_KEY=<키>   # 또는 .env
python scripts/build_scam_dataset.py --per-subtype 40
```
→ 합성(사기+경계) → LLM 라벨 검수(오라벨 탈락) → `data/synthetic/scam/train.jsonl`.
통과/탈락 통계를 확인해 프롬프트·유형 비율을 조정한다.

### S1.5 (선택) 외부 실데이터 씨앗
- PsyScam(공개) 다운로드 → 어댑터로 jsonl 변환(추가 예정 `scripts/adapt_scam_datasets.py`).
- 보이스피싱 벤치마크는 접근 확인 후. 통화체 → 메신저체 정규화 필요.
- 실데이터는 합성 프롬프트의 few-shot 씨앗 + 검수 기준으로 품질을 끌어올린다.

### S2. Fresh blind 확장
- `tests/fixtures/safe_blind_v9.jsonl`에 사기 슬라이스(기관/지인 사칭, OTP, 리딩방 등)와
  경계 반례(정상 금전 대화) 추가. 사기 recall 게이트를 평가에 포함.

### S3. 재학습 (Colab)
- `configs/module1_binary_hardcases_v7.yaml`로 v6과 동일 흐름 재학습.
- dedup: 사기 train이 홀드아웃/blind와 겹치지 않게 빌드 시점 제거(어댑터/빌더에서).

### S4. 평가·게이트
- dev 게이트 + fresh blind v9. 사기 recall과 함께 **정상 오탐(경계 반례) specificity**를
  감시(사기 주입이 정상 금전 대화를 과플래그하지 않는지).

### S5. 배포
- 게이트 통과 시 HF revision 갱신. 모델이 사기를 잡으면 RULE_ASSIST는 belt-and-suspenders로
  재평가(계속 off vs 재활성 — blind에서 룰 on/off 비교).

## 분포 리스크 (감시)

- 합성 사기가 특정 유형(기관 사칭 등)에 몰리면 편향 → 유형별 균형 + 검수 통계로 조정.
- 정상 금전 대화(경계 반례)를 충분히 넣지 않으면 "돈/계좌" 단어만으로 과플래그 → 반례 비율 확보.
- 합성 텍스트의 다양성 부족 → temperature·페르소나·상황 다양화, 실데이터 씨앗으로 보강.

## 경계

- 실제 개인정보(실명·실계좌·전화번호) 합성 금지(프롬프트에 명시).
- 합성·검수는 train 전용. 홀드아웃/blind와 dedup 후 학습.
- 수치 날조 금지 — 검수 통계·평가 실측만 보고.
