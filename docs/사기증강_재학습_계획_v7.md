# SAFE 이진 v7 — 금전 사기 커버리지 보강 계획

상태 기준일: 2026-07-28

## 1. 현재 결론

금전 사기 학습 공백을 메우기 위한 생성·검수·승인·재학습 파이프라인은 구현됐다.
하지만 현재 44행 파일럿은 사람 품질 게이트에 실패했고 승인 manifest가 없으므로
학습에 사용할 수 없다. GPU 재학습, 독립 fresh 평가, HF 업로드도 아직 실행하지 않았다.

`safe_blind_v9.jsonl`은 모델 평가에는 쓰지 않았지만 합성 누수 검사와 데이터 선택에 이미
사용했다. 따라서 최종 성능을 주장하는 strict fresh 셋이 아니며, 최종 평가는 후보 고정 뒤
독립 작성·봉인할 `safe_blind_v10.jsonl`로 한 번만 수행한다.

## 2. 성공 조건

### 데이터 품질

- 사기 6유형, 정상 금전 경계 3유형을 유형별 동일 목표 수로 생성한다.
- label·subtype·source·slice 계약이 정확해야 한다.
- 실제 또는 실제처럼 보이는 전화·계좌·주민번호·OTP·상품권 PIN·URL·이메일이 없어야 한다.
- 라벨 검수, 문장논리 검수, forbidden 누수 제거 뒤 각 subtype이 목표의 80% 이상 남아야 한다.
- 자동 검수 뒤 전수 사람 검수에서 drop 0을 확인하고 revise 원인을 해소해야 한다.
- 후보와 검수 보고서의 SHA를 사람이 명시적으로 승인해야 한다.

### 개발 게이트

- 기존 실 holdout과 소비된 blind v1~v9에서 기존 회귀 기준을 유지한다.
- `scam_recall ≥ 0.80`
- `benign_money_specificity ≥ 0.875`
- repeat 1→3 중 첫 통과 후보를 고정하고 이후 튜닝을 중단한다.

### 독립 fresh v10 게이트

- 전체 `risk_recall ≥ 0.80`
- 전체 `specificity ≥ 0.90`
- 위험 슬라이스 최소 `risk_recall ≥ 0.75`
- `benign_money_specificity ≥ 0.875`
- 평가 전후 blind SHA와 선택 checkpoint tree SHA가 같아야 한다.
- SHA 소비 lock 또는 시작 ledger가 있으면 같은 v10을 다시 평가하지 않는다.

## 3. 파이프라인 설계

```text
Gemini 합성
  → 민감 식별자·스키마·내부 중복 필터
  → LLM label 검수
  → LLM subtype·문장논리 검수
  → 실 holdout·blind v1~v9·grooming 개발셋 exact/near-dup 제거
  → outputs 후보 + 완료 검수 보고서
  → 사람 표본·전수 검수 + SHA 승인
  → canonical train + approval manifest
  → 학습 로더의 manifest·데이터·보고서 SHA 재검증
  → repeat 1~3 개발 게이트
  → 후보·threshold·checkpoint 고정
  → 독립 fresh v10 최초 1회 평가
  → 명시적 사용자 승인 시에만 HF 업로드
```

## 6. 실행 계획

### A. 새 파일럿

```bash
python scripts/build_scam_dataset.py \
  --per-subtype 5 \
  --synth-model gemini-3.5-flash \
  --verify-model gemini-3.5-flash \
  --request-interval 15 \
  --min-retention-ratio 0.8 \
  --out outputs/10_thisabled-ai/데이터/20260728_thisabled_사기파일럿후보_v4.jsonl \
  --synthesis-cache outputs/10_thisabled-ai/데이터/20260728_thisabled_사기파일럿체크포인트_v4.json \
  --verification-report outputs/10_thisabled-ai/데이터/20260728_thisabled_사기파일럿검수보고서_v4.json \
  --forbidden data/eval/aihub_real_holdout.jsonl \
  --forbidden data/eval/beep_real_holdout.jsonl \
  --forbidden data/synthetic/emergency/3a/val.jsonl \
  --forbidden data/synthetic/emergency/3a/test.jsonl \
  $(for i in $(seq 1 9); do echo --forbidden tests/fixtures/safe_blind_v$i.jsonl; done)
```

429가 발생하면 같은 명령을 재실행해 합성 subtype과 검수 배치 체크포인트에서 재개한다.
기존 v3 캐시·보고서는 새 실행에 재사용하지 않는다.

### B. 본 생성·승인

Colab 노트북 셀 3에서 40건/subtype 후보를 생성한다. 완료 보고서와 표본을 확인한 뒤
셀 3b에 후보·보고서 SHA를 입력하고 사람 승인 플래그를 켠다. 이 단계만 canonical train과
approval manifest를 만들 수 있다. `RUN_DATE`는 최초 실행일로 고정해 자정을 넘긴 429
재개에서도 유지하고, 같은 날 새 품질 라운드만 `RUN_VERSION=2, 3, ...`으로 올린다.

### C. 재학습

승인 산출물 검증 뒤 repeat 1→3을 실행한다. 개발 게이트에 처음 통과한 checkpoint와
threshold를 고정하고 checkpoint tree SHA를 기록한다. 세 번 모두 실패하면 fresh 평가와
업로드를 금지한다. 데이터 빌드·외부 adapter 실행 시 v10 파일은 없어야 하며, 실제 base
train + 모든 direct source와 소비 개발셋 사이 exact/near guard가 0건이어야 한다.

### D. 독립 v10과 최종 평가

후보를 고정한 뒤에만 학습 데이터 작성과 분리된 작성자가 v10을 배치하고 SHA를 전달한다.
v10은 정확히 40행·label 20/20, 필수 사기 5개 슬라이스별 최소 3행,
`benign_money` 최소 8행을 만족해야 한다. 노트북은 base train, PAN12를 포함한 direct
source, 실 holdout·blind v1~v9·grooming 개발 평가 텍스트와 exact/near duplicate를
거부한다.

Google Drive의 고정 registry
`/content/drive/MyDrive/thisabled-ai/fresh_blind_registry`와 값이
`thisabled-ai-fresh-blind-registry-v1`인 `.registry_id` marker를 필수로 준비한다.
VS Code가 연결된 Colab 런타임에는 이 Drive 경로가 사전에 마운트되어 있어야 한다.
노트북은 이전 날짜의 v10 ledger를 검색하고 v10 SHA별 소비 lock을 배타 생성한 뒤 시작
ledger를 영속 저장한다. 승인 사기 데이터·검수 보고서·승인 manifest·선택 checkpoint·
blind 정본·평가 결과를 같은 registry에 보존한다. 소비 lock 또는 ledger가 생긴 뒤
누수·스키마·평가 중 어느 단계에서 실패해도 v10은 소비된 것으로 처리하고 재사용하지
않는다.

### E. 배포

v10 게이트 통과 후에만 사용자가 고정 registry의 영속 ledger 경로와 업로드 플래그를
입력한다. 업로드 셀은 별도 세션에서도 registry marker·소비 lock, checkpoint, 승인
사기·보고서·manifest, v10·결과 SHA와 dataset/target/threshold/rule 결합을 검증하고
게이트 수치를 결과에서 다시 계산한다. 업로드 시작·완료 상태를 ledger와 소비 lock
양쪽에 기록하며, 시작 뒤 중단된 실행은 자동 재시도하지 않는다.

## 7. 리스크와 대응

- 합성 편향: subtype 균형, 사람 전수 검수, 실데이터 씨앗으로 완화한다.
- 정상 금전 과탐: `benign_money` 경계 반례와 specificity 게이트로 감시한다.
- 개인정보 우회: 정규화 후 탐지하고 새로운 일반 표기가 발견되면 회귀 테스트를 추가한다.
- 429와 중단: subtype·20건 배치 체크포인트로 재개하되 서버 대기 지시를 우회하지 않는다.
- 부분 저장: 후보와 보고서를 함께 준비하고 rollback 실패 시 복구 백업을 보존한다.
- blind 오염: v9는 회귀용으로만 쓰고, v10은 후보 고정 뒤 독립 작성·1회 소비한다.

## 8. 변경 금지 경계

- 게이트 수치를 결과를 본 뒤 낮추지 않는다.
- v10을 프롬프트·학습·threshold 선택에 사용하지 않는다.
- 승인되지 않은 canonical 사기 파일을 학습하지 않는다.
- 사용자의 명시적 승인 없이 의존성 추가, 외부 데이터 라이선스 결정, HF 업로드를 하지 않는다.
