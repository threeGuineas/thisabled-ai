## 0. 전체 개관

노트북들은 두 흐름으로 나뉜다.

- **A. 4-class 파이프라인 (01~04, 05, 부록)**: EDA로 4단계 라벨 정책 수립 → KcELECTRA 베이스라인 학습 → 평가/리포트 → 누수 안전 재현 파이프라인 → 하이퍼파라미터 튜닝. 라벨은 `정상(0)/주의(1)/경고(2)/긴급(3)`.

## 1. 01_eda.ipynb

**목적**: 두 한국어 시드 혐오표현 데이터(UnSmile + KOLD)를 탐색해 4단계 위험도 라벨 정책(정상/주의/경고/긴급)을 정당화한다.

**입력 · 출력 · 산출물**
- 입력: `data/raw/unsmile/unsmile_train_v1.0.tsv`·`unsmile_valid_v1.0.tsv`, `data/raw/kold/kold_v1.json`. 참조 config `configs/module1_kcelectra.yaml`.
- 산출: EDA 그래프 → `reports/figures/eda/`(`text_length.png`, `unsmile_labels.png`, `kold_grp.png`, `label4_distribution.png`). 데이터 파일 생성 없음.

**주요 단계/셀 흐름**
- 셋업(matplotlib 한글 폰트, 경로) → §1 데이터 로드 → §2 텍스트 길이 분포(char p99≤142 → `max_length=128` 검증) → §3 UnSmile 라벨 분포(멀티라벨 중첩) → §4 KOLD 라벨 분포(OFF/TGT/GRP 교차표) → §5 도메인 적합성("장애" 키워드 커버리지) → §6 시드→4-class 매핑 정책 초안(`unsmile_to_4class`/`kold_to_4class`) → §7 결론.

**실험 맥락 · 결과 · 한계**
- 긴급(3) 클래스가 시드에 거의 없음 → **GPT-4o 합성 필요**. 클래스 불균형 → Focal Loss + class weight 필요. 장애 도메인 과소표현(UnSmile ~86, KOLD ~141) → 합성 시 장애 페르소나 강화.
- 후속 TODO: 결론을 [label_mapping.md](label_mapping.md)로 분리, `src/data/label_mapping.py`·유닛테스트, `build_dataset.py`(parquet), 트레이너 스켈레톤.

**목적**: Colab A100에서 KcELECTRA + Focal Loss 기반 4-class 위험 분류 베이스라인을 학습하고, Gemini로 긴급 합성 데이터를 생성한다.

**입력 · 출력 · 산출물**

- 산출: 체크포인트(`checkpoint-*` + Drive 백업), `reports/figures/module1_confusion_baseline.png`, 메트릭 JSON(`reports/validation_reports/module1/baseline_<ts>.json`), 합성 긴급 데이터 `data/synthetic/emergency/{3a,3b,3c,3d,boundary}/{train,val,test}.jsonl`(~1,170 목표).

**주요 단계/셀 흐름**
- §0 GPU 확인 → §1 private repo 클론(PAT) → §2 의존성 설치 → §3 시드 다운로드·processed parquet 빌드 → §4 스모크 테스트(1-pass + Focal backward) → §5 (선택) Drive 마운트 → §6 `train_module1(...)` 5 epoch → §7 test 평가·혼동행렬(best checkpoint 선택) → §8 메트릭 저장·백업 → §9 다음 단계 → (셀 22~26) Gemini 긴급 합성.

**실험 맥락 · 결과 · 한계**
- 라이브러리: torch, transformers(Trainer), sklearn, google-genai(Gemini 2.0-flash, 무료 15 RPM), 내부 `src.models.focal_loss`·`src.training.trainer`.
- 합성은 재실행 시 이어받고 빈 배치 5회 후 중단(쿼터 보호). 후속: Focal vs CE·class-weight 비교, LightGBM 스태킹, 모듈 ② 시작.

## 4. 04_run_full_pipeline.ipynb

**목적**: [reproducibility_pipeline.md](reproducibility_pipeline.md)를 따르는 **누수 안전 정식 모듈 ① 파이프라인**을 Colab에서 end-to-end 실행한다(MinHash dedup, OOF 로짓 스태킹, MLflow).

**입력 · 출력 · 산출물**
- 입력: `configs/module1_kcelectra_ce.yaml`, 시드·합성 긴급 데이터, `data/processed/*.parquet`. 환경변수: `CONFIG`, `SYNTH_REPEAT=8`, `OOF_FOLDS=5`, `MODEL_DIR`.
- 산출: `data/processed/oof_train_logits.npy`, base+stacking 체크포인트(`models/checkpoints/module1_ce`), MLflow runs(`mlruns/`, experiment "thisabled-module1"), `reports/validation_reports/module1/real_holdout_eval.json`.

**주요 단계/셀 흐름**
- §0 GPU → §1 `main` 클론/체크아웃 → §2 의존성(mlflow·datasketch 확인) → §3 파라미터: 3-1 데이터 빌드(`build_final_dataset.py`, MinHash Jaccard≥0.8 dedup + oversample) → 3-2 base fine-tune → 3-3 OOF 로짓(`generate_oof_logits.py`, fold마다 base 재학습) → 3-4 스태킹(`train_stacking.py`) → 3-5 합성 holdout 평가 → §4 MLflow 결과 표 → (셀 22~25) 실데이터 holdout 평가(`evaluate_real_holdout.py`, `--include-aihub-train` 포함).

**실험 맥락 · 결과 · 한계**
- 이전 파이프라인 대비 개선을 명시: MinHash dedup으로 시드↔합성 누수 차단, OOF-only 로짓으로 in-fold 누수 제거, MLflow 자동 로깅, 4-class 채점 수정.
- **한계**: OOF 단계는 5회 재학습으로 고비용(A100 수 시간, `OOF_FOLDS=3`으로 절감 가능). **합성 Recall은 합성→합성 순환 지표**로 실데이터 일반화가 아님. KPI: 긴급 Recall≥0.80, Macro-F1≥0.75.

## 5. 05_optuna_and_smote_ablation.ipynb

**목적**: 4-class 모델에 대해 (1) SMOTE ablation으로 임베딩 SMOTE가 end-to-end fine-tuning보다 못함을 보여 LLM 증강 채택을 방어하고, (2) Optuna 튜닝 후 (3) 최적 config로 최종 학습한다.

**입력 · 출력 · 산출물**
- 입력: `beomi/KcELECTRA-base-v2022`, 사전 생성된 경고(2) 템플릿 합성 데이터, `configs/module1_kcelectra_optuna_best.yaml`(Optuna 출력으로 **사용자가 생성**).
- 산출: SMOTE ablation 메트릭, Optuna 최적 파라미터, 최종 체크포인트 `models/checkpoints/module1_optuna_best`.

**주요 단계/셀 흐름**
- 셋업(`sys.path`, `chdir`) → §1 임베딩 SMOTE ablation(`scripts/train_embedding_smote.py`, frozen encoder + MLP head) → §2 Optuna 튜닝(`scripts/optuna_search.py --n-trials 30`, TPE로 Macro-F1 최대화 + 긴급(3) Recall≥0.80 하드 제약, MedianPruner). 탐색 변수: `lr`, `warmup_ratio`, `weight_decay`, `alpha` 가중, `warning_augment_ratio` → §3 `best_config`로 `train_module1(..., override_params={"warning_augment_ratio":2.0})`.

**실험 맥락 · 결과 · 한계**
- 논문/제안서의 **방어 논리**로 명시적으로 프레이밍(SMOTE 대신 LLM 증강 정당화). 무거운 셀은 메모리 해제·로깅 안정성을 위해 `!python` 외부 스크립트 호출. GPU 가이드: A100 30~50 trial, T4 20~30. 이 노트북은 4-class(`num_labels=4`) — 아래 이진 노트북과 다름.

**주요 단계/셀 흐름**

## 7. 07_binary_aihub_no_pan_ablation.ipynb

**목적**: 이진 v3 — "시드 + 합성×1 + AI-Hub train"의 누수 없는 조합으로 재학습하되 **PAN12를 제외**해 FP(오탐) 원인을 격리하고, 실데이터 + 그루밍(3a) + warm-normal 회귀셋을 승인 게이트 뒤에서 평가한다.

**입력 · 출력 · 산출물**
- 입력: `configs/module1_binary.yaml`(메모리상에서 `extra_caution_jsonl=[]`로 수정), AI-Hub train, 시드, `data/eval` holdout jsonl, `data_bundle.zip`.
- 산출: `models/checkpoints/module1_binary_aihub_no_pan`, `RESULT` 메트릭 dict, threshold 스윕 후보, **조건부** HF 업로드.

**주요 단계/셀 흐름**
- 1 GPU → 2 클론/동기화 → 3 의존성 → 4 `data_bundle.zip` 업로드 → 5 빌드(`--synth-repeat 1 --include-aihub-train`) → 6 분포 + 누수 사전검사(정규화 후 holdout↔train 무누수 보장) → 7 PAN12 제외 config로 학습 → 8 실 holdout + 3a 그루밍 평가 → 9 고정 warm-normal 회귀셋(`normal_cases`) + 위험 대비셋(`risk_cases`) → 10 승인 게이트 + `RESULT` 저장 → 11~13 규칙 하이브리드 분석(`serving.safety_server.app._rule_hit` 임포트, 모델 vs 모델+규칙 CM, τ 0.50→0.95 스윕) → 14/15 HF 업로드(기본 `UPLOAD_TO_HF=False`, 게이트 PASS 시에만).

**실험 맥락 · 결과 · 한계**

## 특집. 4-class → 이진(2-class) 전환 분석

노트북 05(마지막 4-class 튜닝) → 06(전환 실행) → 07~11(이진 정제)로 이어지는 이 전환은 프로젝트의 최대 방법론적 변곡점이다. 근거 정본은 [safe_라벨_및_판정_기준.md](safe_라벨_및_판정_기준.md)(전환 결정), [재학습_프롬프트_이진_pan12.md](재학습_프롬프트_이진_pan12.md)(실행), [label_mapping.md](label_mapping.md)(구 4-class 매핑).

### A. 과정 — 왜, 어떻게 바꿨나

**① 출발점: 4-class 체계 (연구 단계)**
`0 정상 / 1 주의(무례) / 2 경고(집단 혐오) / 3 긴급(행위 위험: 3a 그루밍·3b 성적 유인·3c 협박·3d 자해)`. 0~2 강도 축 + 3 행위 축의 비대칭 설계였고, **시드(UnSmile/KOLD)에 긴급(3)이 0건**이라 GPT-4o 합성으로 보강했다(노트북 01·02).

**② 직접 계기: 합성→실데이터 전이 실패**
4-class 긴급(3) Recall이 **합성 홀드아웃 1.0** ↔ **실데이터 0.005**로 갈렸다. 합성-only 학습이 실데이터로 일반화되지 못한 것(template-circular). 이 갭이 이진 전환의 방아쇠였다.

**③ 전환 결정 (2026-07-08)** — 학습 라벨을 `정상(0)/주의(1)` 이진으로 재정식화. 근거 4가지:

| 근거 | 설명 |
| --- | --- |
| 서비스 정합 | 명세 SAFE-03 화면 상태가 정상/주의 2개 — 4-class도 어차피 서빙에서 `P(1+2+3)≥τ`로 이진으로 접혔음 |
| 불균형 완화 | 긴급(3) 극소수 클래스 문제(4-class 핵심 난점)가 구조적으로 소멸 |
| 증강 용이 | PAN12 등 외국 그루밍 번역분을 세분 라벨 없이 `주의`로 일괄 라벨링 → 라벨 노이즈 최소화 |
| 판정 단순화 | `verdict = P(주의)≥τ`로 직결, τ 캘리브레이션이 한 확률 축에서 수행 |

**④ 구현 (노트북 06)**
`configs/module1_binary.yaml`: `num_labels=2`, `data.binary=true`로 train/val 라벨 `{1,2,3}→1` 붕괴, loss는 CE·`alpha=[1,1]`(focal/oversample 불필요), `extra_caution_jsonl`로 **PAN12 predator 190건**을 주의(1)로 병합(normal은 성적·거친 내용이라 정상 부적합 — 검수 발견, **미사용**). 정상 보강은 시드 clean(UnSmile clean, KOLD OFF=False)에서.

**⑤ 데이터 보강 트랙**
한국어 그루밍 공개셋 부재(2026-07-08 조사) → 영어 실그루밍 **PAN12**의 predator window만 번역해 주의로 투입. AI-Hub 실데이터(`aihub_train.jsonl`)도 병합. **번역투 편향**("번역체=주의" 오학습) 방지를 위해 정상 대화도 같은 파이프라인으로 번역, 평가 홀드아웃과 번역분은 완전 분리.

**⑥ 서빙 반영**
`serving/safety_server`가 `model.config.num_labels`(2/4)를 자동 감지, `risk_prob = sum(probs[1:])`로 이진·4-class 공용. `/analyze` 계약·응답 형식 불변. 임계값 성인 τ=0.50 / 미성년 τ=0.35 유지.

### B. 결과

**실데이터 홀드아웃 5,491건 (2026-07-08, 첫 시도 통과·추가 튜닝 없음)**

| 지표 | 기준 | 성인 τ=0.5 | 미성년 τ=0.35 |
| --- | --- | --- | --- |
| 주의 Recall (미탐 최소화) | ≥0.80 | **0.859** | **0.899** |
| 정상 Precision (과블러 방지) | ≥0.60 | **0.752** | **0.780** |
| Macro-F1 | — | **0.775** | — |

- 학습 분포 train `{정상 19941, 주의 28386}`, best=epoch1(eval_loss 0.322), seed=42. 혼동행렬 τ=0.5: `[[1440,670],[476,2905]]`.
- **핵심 성취**: 4-class 긴급 실데이터 Recall **0.005 → 이진 주의 Recall 0.859**. 합성-only 전이 실패를 이진 전환 + 실그루밍(PAN12)·AI-Hub 반영으로 구조적으로 해소.
- **불균형 소멸**: 긴급 0.0x% → 정상:주의 ≈ 42:58. class weight·Focal·oversample 없이 기본 CE로 학습 가능.
- **이후 개선**: 06 → 07(PAN12 제외 ablation) → 08~11 하드케이스 반복으로 슬라이스·FP를 정제, 최종 **v4_r1** 채택(fresh blind 기준 risk_recall 1.0, macro-F1 0.975). 상세는 [safe_이진_모델_개선_실험보고서.md](safe_이진_모델_개선_실험보고서.md).

### C. 한계

1. **정보 손실 (설계상 트레이드오프)**: 위험 유형·수위 세분(1주의/2경고/3긴급, 3a~3d)을 포기. SAFE-04 내부 위험 점수의 수위별 가중은 후속(4-class 헤드 병행 또는 멀티태스크)으로 이월. 4-class 연구 성과(매핑 정책·실측)는 보고서에 "연구:4단계 → 운영:서비스 요구(2단계)" 서사로 보존.
2. **평가셋 독립성**: 실데이터 홀드아웃은 AI-Hub/BEEP(혐오·비도덕 중심). **그루밍 특화 실데이터 홀드아웃은 부재** — 그루밍 검증은 저자 생성 blind(합성)로 *패턴 일반화*만 측정한다.
3. **번역투 편향 잔존 리스크**: PAN12는 영어 번역분. 정상도 번역 투입해 완화했으나 문체가 아닌 내용으로 구분함을 완전 입증하진 못함(노트북 06·07의 편향 점검·대조셋으로 상시 감시).
4. **잔여 중복**: BEEP holdout↔KOLD train 정규화 중복 2건(양쪽 정상, 실질 무해), AI-Hub train 병합 시 홀드아웃 중복 3건 선제거 필요(후속).
5. **금전 사기 커버리지 약함**: 시드가 혐오표현 중심 → 사기 유형 미흡. 규칙 보조 레이어로 보완하나 정상 부정문 오탐 탓에 현재 **OFF** 운영. 근본 해결은 사기 합성 증강 + 재학습.
6. **그루밍 원데이터 제약**: PAN12는 아동 대상 범죄 실데이터 — 재배포 금지·저장소 원문 커밋 금지, 무료 티어 쿼터로 250 중 190건만 확보.
